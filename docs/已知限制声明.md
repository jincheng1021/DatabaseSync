# 已知限制声明

> 交付版本 0.5.0-M5。以下限制在设计方案 §11/§14/§18 中明示，随交付文档一并声明。

## 1. 大事务流式提交（E8）

单事务超过阈值（默认 100,000 行，`big_tx_threshold_rows` 可调）时切换「边读边写」流式提交：

- **限制**：拆散源事务边界，部分子变更先行可见，过程态事务原子性不再保证；
- **兜底**：失败重试由幂等写（REPLACE / 按主键 DELETE）吸收，最终一致不受影响；
- 告警文案明示此语义（`cdc_big_tx`）。

## 2. 多唯一索引表（E15）

REPLACE 幂等写为「先删后插」语义。目标表含 **2 个及以上唯一索引** 时，任一唯一键冲突可能删除多行，删除范围可能超出源库变更语义：

- **缓解**：源库预检对多唯一索引表给出 warn 提示（`multi_unique_index`）；
- **定位前提**：目标库为只读副本场景下风险可控；
- **兜底**：校验服务（行数/checksum/行级 diff）可发现差异。

## 3. 子集同步语义

按行过滤（row_filters）的子集同步：

- 禁用孤儿清理（删除类修复一并禁用）——无法区分「源库已删」与「不在同步范围」；
- 退出范围 UPDATE 转目标 DELETE，防止越界行污染；
- 重刷缓存队列对涉及表照常生效。

## 3a. 孤儿清理语义与保险丝（2026-10-12 修复后口径）

孤儿行清理以**源库当前态**为基准删除「目标有源无」行，存在性比较**全部发生在目标端 MySQL 内**
（临时表镜像目标 PK 列类型/collation），与 REPLACE 写入语义一致——历史上 Python 码点序与
MySQL collation 序混比曾导致中文主键 + 全角括号值表（lw_bzun）误删 79 行，已修复。

- **保险丝**：源库 0 行而目标非空 → 整表拦截并 error 告警（疑似源库被清空/配错库）；
  待删行数 > max(`orphan_guard_min_rows`，目标行数 × `orphan_guard_max_ratio`) → 整表拦截并
  warning 告警，需人工用「预览孤儿清理」（dry-run）确认后处理；
- **跳过登记**：无主键/复合主键/行过滤子集/源表指纹漂移/PK 类型跨族/清理异常均登记于 run 报告
  `orphan_skipped`，不再静默；
- **前置条件**：目标端账号需 `CREATE TEMPORARY TABLES` 权限（临时表会话结束自动消亡）；
- **跨任务同物理目标表并发清理**属既有风险，保险丝可拦截大部分误删场景，建议规划上避免。

## 4. 触发器不迁移（默认）

- 目标库默认**不建触发器**（避免删插语义二次触发业务逻辑）；
- 任务级「触发器迁移」开关默认关，开启需红色风险确认；
- 迁移的触发器不会同步其触发产生的数据变更（源库触发器产生的变更已包含在 binlog 行事件中）。

## 5. 外部备份文件不支持恢复（O13）

恢复对象仅限**本工具生成的 .sql 产物**（依赖文件头环境声明与 rows_json 行数基线）。mysqldump 等外部工具产物的回放兼容已在 §18 O13 登记排期，本期不支持。

## 6. 恢复不做断点续传

恢复为单 worker 顺序回放（保证语句顺序语义）；中断后目标库标记「恢复未完成」，指引整体重跑（依赖安全网备份或覆盖式恢复重来）。

## 7. 校验会话时区统一口径

校验会话两端统一 `time_zone = 源库 @@session.time_zone`；若目标库需独立时区语义，时间类列的比对以源库时区为准。
