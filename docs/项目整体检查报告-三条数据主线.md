## 三、待优化清单（P2/P3，本次未改）

### 增量 CDC
1. **DDL「执行/记住执行」未应用 rename/前后缀映射**：`_execute_ddl_on_target` 按源表名原文执行 → rename 配置下目标结构漂移（cdc_engine.py:598-608）。
2. **eval_predicate 类型口径**：全量（PyMySQL）与增量（mysql-replication）行值类型存在差异，`==` 严格比较可能使子集表两链路筛选分叉（cdc_transform.py:27-34）。
3. **skip 掉的 DDL 位点不推进**：DDL 后无行事件时，重启会再次拦截同一 DDL（cdc_engine.py:591-594，影响有限）。
4. `stop()` 与 applier 异常路径存在 run 终态双写竞态（cdc_engine.py:273-276，概率低）。
5. `parse_affected_tables` 正则对 RENAME/多表 DDL 偏弱，影响 DDL 记忆粒度（cdc_transform.py:120-127）。
6. `monitor_tick/get_stats` 直读 queue/counters 无锁（仅观测影响）。

### 备份/恢复
7. **备份位点与数据弱一致**：capture_position 自连取位即解锁，导出连接二次 FTWRL 间隙位点可漂移（备份数据自洽，仅 position 头与数据不严格对应；用该 position 续 CDC 需注意）（full_engine.py:112-113 + backup_service.py:155-160）。
8. **二进制列保真**：`_insert_sql` latin1+`_binary''` 经 utf8mb4 回放字节不可还原且 `\` 未转义，建议改 `0x...` 十六进制字面量（backup_service.py:267,273）。
9. NO_BACKSLASH_ESCAPES 模式下字符串 `\\` 双写损坏（backup_service.py:273）。
10. 恢复互斥仅按 backup_id，不同备份并发恢复同一目标库无互斥；恢复全程目标库无写锁（外部写入者可污染校验）（restore_service.py:160）。
11. rows_baseline 存 SQLite 未内嵌备份文件，DB 记录丢失后校验失据（backup_service.py:214-225）。
12. 恢复校验口径建议在 precheck/报告中显式提示「与备份快照比，非与源库实时比」，避免与 VerifyService 口径混淆（认知层面）。
13. backup/restore 引擎线程进度缺失（备份无行进度、restore 万分比乱值）；run_table_detail 恢复全程不更新（永远 pending）。

### 全量
14. 无主键表 LIMIT/OFFSET 断点窗口内源库写入会漂移（结构性限制，已在 UI 警告）。
15. capture_position 无锁快照立即 ROLLBACK，P0 与拷贝窗口一致性靠 CDC 幂等兜底（M3 遗留 TODO，建议后续挂起快照事务）。

### 横切
16. `_threads` 字典只增不删（full_engine/verify/orphan/restore 四处，轻微泄漏）。
17. pk_mode 仅 verify 读取，全量/CDC/validator 均忽略（口径形同虚设，建议要么落地要么下架该配置）。
18. 测试缺口：全量引擎（_copy_one/断点/暂停恢复）零直接测试；restore 端到端、precheck、_replay_cache 异常分支无覆盖（本次仅补 2 个回归锚点）。
